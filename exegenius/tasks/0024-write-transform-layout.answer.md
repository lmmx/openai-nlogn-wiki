Transform layout is a permutation of address bits that puts the selected bits of several axes at one common offset, in consecutive chunks, so that a single pass can apply a whole transform round. It is the step that lets the [simultaneous butterfly layer](simultaneous-butterfly-layer.md) act on a multi-axis transform, and its cost is part of the bound for [Integer multiplication below n log n](main-theorem.md).

Each entry of a multidimensional array sits at a binary address, and the bits of that address are the *address bits*. Each coordinate of the array is an *axis*. A *transform round* applies one two-point butterfly on each participating axis. The butterfly is $H_0(u,v) = ((u+v)/2, (u-v)/2)$ on a pair of entries that differ in one selected bit.<cite data-source="paper">H0 (u, v) = ((u + v)/2, (u − v)/2)</cite><cite data-source="paper">A round applies one current H0 on each participating axis.</cite>

The shape a round needs is fixed by two numbers. Here $K$ is the number of address bits in each chunk and $D$ is the number of participating axes, each of which contributes one chunk of $K$ consecutive address bits. <cite data-source="paper">Its D consecutive K-bit chunks each select the bit at</cite><cite data-source="paper">one common offset 0 ≤ ρ < K, counted from the least significant end.</cite> Here $\rho$ is that common offset, the position of the selected bit within each chunk, counted from the least significant bit.

The simultaneous butterfly layer is defined on exactly this shape. <cite data-source="paper">On each of the D consecutive K-bit address chunks, select bit ρ, numbered from the least</cite> It applies $H_0$ to the selected bit of every chunk in one evaluation, and <cite data-source="paper">fixes every unselected address bit</cite>

Without this shape, a round would need one pass per axis: <cite data-source="paper">separate butterfly factors would require D whole-array passes.</cite> The layout moves the selected bits of all participating axes into the shape above, so that one pass of the layer serves the whole round. The layout prepares the input for each [simultaneous butterfly layer](simultaneous-butterfly-layer.md) of a transform round.

The layout is an explicit permutation $L$ of record addresses. <cite data-source="paper">constructs an explicit positional layout permutation L of record addresses, preserving their polynomial suffixes</cite> The coefficients of each record stay together as a contiguous block of its address, the record's <cite data-source="paper">polynomial’s coefficients in a contiguous suffix.</cite>

The layout is built from [address-field interchange](address-interchange.md) moves of whole chunks, together with single-bit moves. <cite data-source="paper">The layout uses the single-bit moves of Lemma 3</cite><cite data-source="paper">and the chunk interchanges of Lemma 12</cite> The construction has two phases. In the first, <cite data-source="paper">Move each listed slot immediately after the prefix already formed</cite> so the bits that must be selected are gathered into a prefix. In the second, the chunks outside that prefix are reordered: <cite data-source="paper">consists of q consecutive K-bit chunks.</cite> Their order is changed so that the chunks of all $D$ axes at the same chunk index sit next to each other, and the layer is applied to each such group of $D$ consecutive chunks.

Here is a small example of the target shape, not of the procedure's own steps. Take $K = 2$, $D = 2$, $\rho = 1$, and 6-bit addresses with bit positions $0$ to $5$, counted from the least significant bit. The layer then needs the two selected bits at positions $1$ and $3$, which are the second bits of the chunks at positions $\{0,1\}$ and $\{2,3\}$. If the selected bits start at positions $0$ and $5$, exchanging positions $0$ and $1$ and exchanging positions $3$ and $5$ puts them at positions $1$ and $3$.

The layout is charged in full. <cite data-source="paper">Both layout construction and final restoration are charged in this bound.</cite> The forward transform may keep its output order: it can <cite data-source="paper">retain its output layout for a pointwise product and the following opposite procedure.</cite> The frequency entries therefore stay in layout order through the pointwise product, and the opposite transform reads them in that order. The layout is applied within each round of the [synthetic polynomial transforms](synthetic-transforms.md).
