An address field is a run of bits in the [address](address.md) of an array, consecutive in position, and it is the unit that an address interchange exchanges with another field of the same width. The paper's tape multiplication depends on these interchanges to change how an array's entries are laid out on the tape: <cite data-source="paper">Fast address interchanges organize the layouts</cite>.

The paper also calls a field an address chunk or a chunk: <cite data-source="paper">We use the bit network to interchange two equal address chunks on tape</cite>, where the two chunks are the two fields that the interchange swaps.

An array is stored as one ordered stream: <cite data-source="paper">stored in lexicographic order, with the first coordinate most significant</cite>. Lexicographic order is dictionary order: the first coordinate decides, and later coordinates break ties. <cite data-source="paper">An address is implicit in an entry’s position in this ordered stream</cite>, so no address is written beside each bit. The addresses form a complete Cartesian product: every combination of coordinate values, each coordinate ranging over all its values, occurs as an address.

Write $\rho$ for the field width, the number of bits in each of the two fields being interchanged. The paper writes $u$ for this width; this page uses $\rho$ so that $u$ keeps its other meanings. Bit positions are numbered from 1 at the most significant bit, so position 1 is the leftmost. A field of $\rho$ bits is a run of $\rho$ consecutive positions, and two fields are disjoint when they share no position. The paper's first procedure <cite data-source="paper">interchanges two disjoint contiguous address fields of u bits in an array</cite>, <cite data-source="paper">whose addresses form a complete Cartesian product</cite>.

Take $\rho = 2$ and an array of 16 entries with 4-bit addresses, with the two fields at bit positions 1–2 and 3–4. The interchange sends address $0110$ to $1001$, because the field $01$ and the field $10$ trade places. So the entry stored at $0110$ moves to $1001$. Likewise the fields $00$ and $11$ of $0011$ trade places, and the entry at $0011$ moves to $1100$.

Each address field is moved by a [permutation](permutation.md) of addresses, because the interchange exchanges only the fields and not the entries' values. The paper's definition is <cite data-source="paper">An address permutation f moves the entry at x to f (x).</cite>

Contiguity keeps each move local in the stream. Fix the bits before the field; in the example these are positions 1 and 2. The entries that match this prefix form one run of consecutive stream positions, and within that run the field's bits take every value. The four entries beginning with $01$ occupy stream positions $4$ to $7$, counting from $0$. A tape head can carry such a run out in one left-to-right sweep, so the run is handled as one block. Without contiguity, the entries that move together would be spread across the stream, and the head would have to jump between them. The paper's first procedure is stated for contiguous fields only.
