A fixed-tape machine is a Turing machine whose alphabet and number of one-dimensional tapes are both fixed in advance, so neither grows with the input. The paper's main result is stated in this model, so the model fixes what running time means there.

A step of the machine reads and writes at most one cell on each tape, and moves each head by at most one cell. <cite data-source="paper">A step reads and writes at most one cell on each tape and moves each head by at most one cell.</cite> Extra tracks and a finite number of work tapes are allowed, because they only change running time by a fixed factor. <cite data-source="paper">Fixed tracks and finitely many work tapes change time by a fixed factor.</cite> Each scan also includes its own counters and the return of its heads, which costs only a bounded amount per scan.

The model separates two kinds of rearrangement. Moving one digit in a fixed radix needs a bounded number of scans, because the digit is a constant-size object. Interchanging two fields whose numbers of digits grow with the input is different, since the number of scans it needs grows with the field width. The paper therefore builds such interchanges from elementary scans and XOR combinations of data streams, rather than assuming them as primitive.

For example, a machine that moves the last cell of a block of three cells to the front uses a fixed sequence of scans, whatever the contents of the cells. Its running time is a constant that does not depend on the alphabet of the data, since the alphabet is fixed. A machine that swaps two fields of $u$ cells each needs time that depends on $u$, so the same kind of fixed sequence cannot be used for it.
