An array is a finite collection of entries, each stored at an [address](address.md) and carrying a [payload](payload.md). The paper's tape procedures act on arrays. A tape procedure is a procedure run on a multitape Turing machine that rearranges an array held on its tapes. Here $V$ is the number of stored data bits, the paper's logical volume. The paper's elementary array operations, such as fixed permutations of digit values, each <cite data-source="paper">takes O(V ) steps on a fixed number of one-dimensional tapes</cite>. The [address-field interchange](address-interchange.md) and the [linear networks](linear-network-frames.md) of the argument are likewise operations on arrays, and their costs are measured by $V$.

The entries of an array are indexed by their [address](address.md). Each entry carries a [payload](payload.md), the record data stored at its address. The paper's array is <cite data-source="paper">stored in lexicographic order, with the first coordinate most significant.</cite> Lexicographic order compares two addresses by their first coordinate and, when those agree, by the next coordinate, and so on. The order fixes every address, so the paper can state: <cite data-source="paper">An address is implicit in an entry’s position in this ordered stream;</cite> it is not stored beside every data bit.

For example, take the addresses 00, 01, 10 and 11 in that order, with one-bit payloads 1, 0, 1 and 1. The array is the stream 1011 on one tape, and $V = 4$. The payload at address 10 is the third bit of the stream, so changing it writes no address bits.

The paper's term disk array names an array that <cite data-source="paper">has norm at most one.</cite> Here the [norm](array-norm.md) of an array is the maximum modulus over all coefficients in all its entries, so every coefficient of a disk array has modulus at most one.
