Bit-reversed index order is the arrangement of an array of $2^d$ entries in which each entry sits at the slot whose number is its address read backwards. The order reverses the bits of each [Address](address.md) $\alpha$ to find the slot that stores its entry. The argument uses it as the output order of a transform on $2^d$ entries: <cite data-source="paper">The recursion writes its outputs directly in this order; it does not move whole frequency indices.</cite>

Write an address as a string of bits $\alpha_{d-1}\cdots\alpha_0$, where $\alpha_s \in \{0,1\}$ is the bit with weight $2^s$, so its position number is $\sum_{s=0}^{d-1}\alpha_s 2^s$. The reversal map $\rho_d$ sends each $d$-bit address to the address with the same bits in the opposite order, $\rho_d(\alpha_{d-1}\cdots\alpha_0)=\alpha_0\cdots\alpha_{d-1}$. Its slot number is $\rho_d(\alpha)=\sum_{s=0}^{d-1}\alpha_s 2^{d-1-s}$, so bit-reversed index order stores the entry at address $\alpha$ in slot $\rho_d(\alpha)$. Applying $\rho_d$ twice returns the original address, so every slot is filled by exactly one address.

For $d = 3$, the addresses $000$ through $111$ are reversed to $000, 100, 010, 110, 001, 101, 011, 111$. Slots $0$ through $7$ therefore hold the entries at addresses $0, 4, 2, 6, 1, 5, 3, 7$. For example, address $011$ has $\alpha_0 = \alpha_1 = 1$ and $\alpha_2 = 0$, so $\rho_3(011) = 110$, and its entry sits in slot $6$.
