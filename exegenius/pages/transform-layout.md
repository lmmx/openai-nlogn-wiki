A transform layout is a permutation of record addresses. The transform layout places the selected bits of every [participating axis](transform-axis.md) at one common offset, so one pass can apply a butterfly to all of them. The transform layout prepares the input for each [simultaneous butterfly layer](simultaneous-butterfly-layer.md) of a transform round. Its cost is charged in the bound for [integer multiplication below n log n](main-theorem.md).

Each coordinate of an array is an *axis*. <cite data-source="paper">Each address carries a polynomial record with r complex coefficients</cite>, whose coefficients form a contiguous block of trailing address bits, its *polynomial suffix*. The transform layout $\mathcal{L}$ is an explicit [permutation](permutation.md) of record addresses. <cite data-source="paper">a record at address x moves to address Lx, while its polynomial suffix stays intact.</cite> The transform layout keeps each element of the [polynomial ring](polynomial-ring.md) that a record holds intact.

A round's *selected bits* are the bits on which its [butterfly](butterfly.md) acts, defined by <cite data-source="paper">H0 (u, v) = ((u + v)/2, (u − v)/2)</cite>. A round applies one such butterfly on each participating axis.

Here $D$ is the number of participating axes, and $K$ is the number of bits in each chunk; $K$ has other meanings on earlier pages. A round needs its selected bits in $D$ consecutive $K$-bit chunks. <cite data-source="paper">Its D consecutive K-bit chunks each select the bit at one common offset 0 ≤ ρ < K, counted from the least significant end.</cite> Here $\upsilon$ is that offset, the position of the selected bit within its chunk, with $0\le\upsilon<K$. The transform layout counts its offsets from the [least significant end](address.md) of each address.

The shape makes one pass enough. A pass applies a two-point map at one bit position in each chunk, so the selected bits are handled together only when they share an offset. Otherwise <cite data-source="paper">separate butterfly factors would require D whole-array passes.</cite>

A *long* axis has $\lg r$ address bits and a *short* axis has $\lg r-1$, where $\lg r$ is the base-two logarithm of $r$. Let $(\lg r-1)\bmod K$ be the remainder of $\lg r-1$ on division by $K$. The layout first moves a prefix to the front: the top bit of each long axis, then the bits at positions $(\lg r-1)\bmod K-1$ down to $0$ of every axis, highest position first, with axes in order within each position. <cite data-source="paper">Move each listed slot immediately after the prefix already formed, leaving all other slots in their relative order.</cite>

The remaining bits of each axis, at positions $(\lg r-1)\bmod K$ to $\lg r-2$, form $\lfloor(\lg r-1)/K\rfloor$ consecutive $K$-bit chunks, where $\lfloor x\rfloor$ is the largest integer not exceeding $x$. Numbering the chunks from the highest down, the layout exchanges chunks so that the $D$ chunks with the same number are adjacent: <cite data-source="paper">exchange the chunk currently there with the required chunk if they differ.</cite> The transform layout is built from [address-field interchange](address-interchange.md) moves of whole chunks, together with single-bit moves. Each movement is <cite data-source="paper">included in the transform cost.</cite>

A round on the bit at position $\varsigma$, counted from the least significant end, with $(\lg r-1)\bmod K\le\varsigma\le\lg r-2$, selects offset $(\varsigma-((\lg r-1)\bmod K))\bmod K$ within its chunk. Every axis has the same remaining positions, so the chunks with the same number share this offset: <cite data-source="paper">in each of the D consecutive chunks with the same chunk index j.</cite>

Take $\lg r=6$ and $K=2$, with one long and one short axis. Then $(\lg r-1)\bmod K=1$, and positions $1$ to $4$ form chunks $\{4,3\}$ and $\{2,1\}$ on each axis. A round at $\varsigma=4$ selects offset $1$ in both $\{4,3\}$ chunks, so one pass handles both.

The transform layout is the output order retained by the [forward procedure](forward-transform.md) for a pointwise product and the following opposite procedure. <cite data-source="paper">The forward procedure may retain its output layout for a pointwise product</cite>, and <cite data-source="paper">Pointwise multiplication commutes with applying the same record permutation</cite>, so the outputs can be multiplied in their [retained order](transform-identity.md). The transform layout is consumed by the [opposite transform](opposite-transform.md). <cite data-source="paper">consumes that same order after a pointwise product.</cite>

The transform layout is applied within each round of the [synthetic polynomial transforms](synthetic-transforms.md). <cite data-source="paper">we must place the selected bits of the participating axes at a common offset</cite> The transform layout follows the pattern of the [transform identity with retained permutations](transform-identity.md), keeping its permutation in the computation.
