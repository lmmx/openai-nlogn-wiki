Exact integer multiplication is the task of computing the complete product of two binary integers, with no rounding and no bits lost. The main result bounds the cost of this task ([Integer multiplication below n log n](main-theorem.md)), and its method begins by splitting each input into digits, which reduces the product to a convolution ([radix-digit convolution](radix-digit-convolution.md)). <cite data-source="paper">Splitting the inputs into radix digits reduces multiplication to convolution of short integer coefficients.</cite>

Here $n$ is the number of bits in each input. Let $x$ and $y$ be binary strings, each of length $n$. For a binary string $x$ of length $n$, $\mathrm{val}(x)$ is its nonnegative integer value, with the leftmost bit most significant. <cite data-source="paper">For a binary string x of length n, let val(x) be its nonnegative integer value, with the leftmost</cite> For $0 \le z < 2^k$, $\mathrm{bin}_k(z)$ is the binary representation of $z$ padded on the left with zeros to length $k$. <cite data-source="paper">denote its binary representation padded on the left to length k</cite>

The input is the string $x\#y$, and the output must be $\mathrm{bin}_{2n}(\mathrm{val}(x)\cdot\mathrm{val}(y))$, the $2n$-bit representation of the product. <cite data-source="paper">We consider exact multiplication: on input x#y, with x, y ∈ {0, 1}n , the output must</cite> The output has $2n$ bits because each value is at most $2^n - 1$, so the product is below $2^{2n}$.

For example, take $n = 2$, $x = 10$ and $y = 11$. Then $\mathrm{val}(x) = 2$ and $\mathrm{val}(y) = 3$, so the product is $6$, and the required output is $\mathrm{bin}_4(6) = 0110$.

Exactness must hold for every input length, not only for large $n$. <cite data-source="paper">The algorithm is exact for every input length</cite> Costs are measured on a machine whose alphabet and number of tapes are fixed in advance. <cite data-source="paper">A machine has one fixed finite alphabet and one fixed finite number of one-dimensional tapes.</cite> The machine does not change as $n$ grows; only the input does.

The classical question is how fast this product can be computed. <cite data-source="paper">Schönhage and Strassen conjectured n log n as the optimal order of multiplication cost</cite> (see [the n log n optimality conjecture](n-log-n-conjecture.md)).
