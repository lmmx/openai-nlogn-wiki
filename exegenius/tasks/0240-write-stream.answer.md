A stream is the order in which a procedure visits its data on a tape: a sequence of records that the procedure reads or writes in order, one position at a time. The tape procedures of the argument are built from scans of streams, so the cost of each procedure is counted in such scans, and this page defines the object they scan. A record is a fixed-length group of stored bits or values that occupies one position in a stream.

Streams are needed because a tape head cannot jump. <cite data-source="paper">A step reads and writes at most one cell on each tape and moves each head by at most one cell.</cite> Reaching a cell far from the head therefore costs as many steps as the distance, so a procedure that is to run in near-linear time must visit its data in order. A scan is one pass of a head over a stream from its first position to its last, followed by the return of the head to the start. The paper counts that return as part of the scan: <cite data-source="paper">Every scan includes its counters and the return of its tape heads.</cite>

A stream lists the entries of an [Array](array.md) in address order. Its positions are not addresses. A stream position is the index of a record within its stream, counted from the first record, and the array address of a record is a different number. Since the position already fixes the address, the stream does not store it: <cite data-source="paper">An address is implicit in an entry’s position in this ordered stream; it is not stored beside every data bit.</cite>

Take an array of eight entries a, b, c, d, e, f, g, h, stored in that order and grouped into four rows of two entries: (a, b), (c, d), (e, f), (g, h). Split the rows alternately into two streams, rows 1 and 3 into the first and rows 2 and 4 into the second. The first stream is a, b, e, f and the second is c, d, g, h. The entry e has array address 5 but stream position 3 in the first stream. Each stream is then scanned once from its first entry to its last, so the work on each stream is proportional to its length.

Splitting and merging are the operations that create and recombine streams. The tape lemmas rely on splitting an array on a digit, transforming aligned streams, and merging them back in linear time. <cite data-source="paper">splitting on a specified radix-q digit, applying a fixed pointwise map to aligned streams, and merging them back</cite>

The network procedures use the same idea with rows. Each procedure is a fixed network whose wires each carry one stream. A wire's fixed place in the network is called its role, and the stream that a role carries is its role stream. <cite data-source="paper">All role streams have the same local address set</cite>, so every role stream can be processed by the same scan.

Fixed tracks are a further kind of stream storage in the paper. <cite data-source="paper">Fixed tracks and finitely many work tapes change time by a fixed factor.</cite> Using them therefore does not change the order of the running time.
