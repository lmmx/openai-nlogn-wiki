Transform layout is an explicit permutation $L$ of record addresses, which preserves each record's polynomial suffix. It places the selected bits of all participating axes at one common offset, in consecutive chunks, so that one pass of a [simultaneous butterfly layer](simultaneous-butterfly-layer.md) applies a whole transform round. Its cost is part of the bound for [Integer multiplication below n log n](main-theorem.md).

Each entry of a multidimensional array sits at a binary address, whose bits are the *address bits*. Each coordinate of the array is an *axis*. Each address holds one *record*, the polynomial with $r$ complex coefficients stored there. A *transform round* applies one two-point butterfly on each participating axis, the map $H_0(u,v) = ((u+v)/2, (u-v)/2)$ on a pair of entries that differ in one selected bit.<cite data-source="paper">H0 (u, v) = ((u + v)/2, (u − v)/2)</cite><cite data-source="paper">A round applies one current H0 on each participating axis.</cite>

The shape a round needs is fixed by two numbers. $K$ is the number of address bits in each chunk, and $D$ is the number of participating axes, each contributing one chunk.<cite data-source="paper">Its D consecutive K-bit chunks each select the bit at</cite><cite data-source="paper">one common offset 0 ≤ ρ < K, counted from the least significant end.</cite> The simultaneous butterfly layer is defined on exactly this shape.<cite data-source="paper">On each of the D consecutive K-bit address chunks, select bit ρ</cite> It applies $H_0$ to the selected bit of every chunk in one evaluation, and it fixes every unselected address bit.<cite data-source="paper">fixes every unselected address bit</cite> Without this shape, a round would need one pass per axis.<cite data-source="paper">separate butterfly factors would require D whole-array passes.</cite>

A record moves from its address to the address that $L$ assigns to it, with its coefficients intact.<cite data-source="paper">a record at address x moves to address Lx, while its polynomial suffix stays intact.</cite><cite data-source="paper">The coefficients of each polynomial form a contiguous suffix.</cite> The layout prepares the input for each [simultaneous butterfly layer](simultaneous-butterfly-layer.md) of a transform round.

The layout is built from [address-field interchange](address-interchange.md) moves of whole chunks, together with single-bit moves.<cite data-source="paper">The layout uses the single-bit moves of Lemma 3</cite><cite data-source="paper">and the chunk interchanges of Lemma 12</cite> Here $\ell$ is the base-two logarithm of $r$, so a long axis has $\ell$ address bits and a short axis has $\ell-1$.<cite data-source="paper">Call an axis long if ai = ℓ and short if ai = ℓ − 1.</cite>

The first phase gathers the selected bits into a *prefix*, the leading part of the physical bit order. It takes the top bit of each long axis, then the bits at positions below $(\ell-1) \bmod K$, from the highest position down, with the axes in order within each position.<cite data-source="paper">Move each listed slot immediately after the prefix already formed</cite> Other bits keep their relative order.

The second phase reorders the chunks. Each axis's part outside the prefix<cite data-source="paper">consists of q consecutive K-bit chunks.</cite> Number each axis's chunks from the highest down, so a chunk's *chunk index* is its number. The reorder puts the $D$ chunks with the same index next to each other.<cite data-source="paper">in each of the D consecutive chunks with the same chunk index</cite> Each such group carries the selected bits at one common offset, which is the shape the layer needs, so the layer is applied to each group. The reorder uses chunk exchanges.<cite data-source="paper">exchange the chunk currently there with the required chunk if they differ.</cite> The inverse $L^{-1}$ undoes them in reverse order.<cite data-source="paper">Recording the inverse operations in reverse order gives L−1 with the same cost.</cite>

The layout is charged in full.<cite data-source="paper">Both layout construction and final restoration are charged in this bound.</cite> Every single-bit move and chunk exchange, in building $L$ and in restoring the order, is counted in the bound. The bound is the total cost of the procedure, so leaving the layout out would leave out one of its steps.

For example, take $K = 2$, $D = 2$, $\rho = 1$, and 6-bit addresses with bit positions $0$ to $5$. The layer needs the selected bits at positions $1$ and $3$, the second bits of the chunks $\{0,1\}$ and $\{2,3\}$. If the selected bits start at positions $0$ and $5$, exchanging positions $0$ and $1$ and positions $3$ and $5$ puts them there.

The forward transform may keep its output order.<cite data-source="paper">retain its output layout for a pointwise product and the following opposite procedure.</cite> This is possible because pointwise multiplication commutes with applying the same record permutation $L$ to both operands.<cite data-source="paper">Pointwise multiplication commutes with applying the same record permutation</cite> The layout feeds its retained order to the [opposite transform](opposite-transform.md), which consumes that order. The layout is applied within each round of the [synthetic polynomial transforms](synthetic-transforms.md).
