A permutation is a rearrangement of a finite set of positions: a map that moves every position to another, so that every position is filled exactly once. It moves stored data without changing any value. The page [Address-field interchange](address-interchange.md) builds on it, because swapping two blocks of address bits is a permutation of an array's addresses.

Here $\mathcal P$ is the finite set of positions, and $\upsilon$ is a permutation of it, the map that sends each position to its new position. A permutation of $\mathcal P$ is defined as a [bijection](bijection.md) of $\mathcal P$ onto itself, that is, a map $\upsilon$ from $\mathcal P$ to $\mathcal P$ that is one-to-one (no two positions have the same image) and onto (every position is an image). Because $\upsilon$ is a bijection, it has an inverse $\upsilon^{-1}$, and $\upsilon^{-1}\circ\upsilon$ is the identity map $\mathrm{id}$, so the move can be undone.

**Rearranging a sequence.** Let $\mathcal P=\{1,2,3,4\}$ with $\upsilon(1)=3$, $\upsilon(2)=1$, $\upsilon(3)=4$ and $\upsilon(4)=2$. Four entries, named $\mathsf a$, $\mathsf b$, $\mathsf c$ and $\mathsf d$ for this example only, sit at positions 1 to 4. Applying $\upsilon$ moves the entry at each position to its image: $\mathsf a$ goes to position 3, $\mathsf b$ to position 1, $\mathsf c$ to position 4 and $\mathsf d$ to position 2. The sequence $(\mathsf a,\mathsf b,\mathsf c,\mathsf d)$ becomes $(\mathsf b,\mathsf d,\mathsf a,\mathsf c)$, and every position is filled exactly once.

The bijection property keeps every entry. If $\upsilon$ were not one-to-one, two entries would land in one position and one would be overwritten. If it were not onto, some position would stay empty. Both failures lose data, while a bijection only moves it.

**Permutations of addresses.** Let $X$ be an array whose entries are stored at addresses $\alpha$, and let $\upsilon$ be a permutation of the set of addresses. The paper writes such a map as $f$, with the address written $x$, and states: <cite data-source="paper">An address permutation f moves the entry at x to f (x).</cite> The moved array $X'$ holds each entry at its new address, so $X'(\upsilon(\alpha))=X(\alpha)$ for every address $\alpha$.

For example, take two-bit addresses and let $\upsilon$ swap the two bits of an address. It sends $01$ to $10$ and $10$ to $01$, and it fixes $00$ and $11$. The entry stored at $01$ therefore moves to $10$. No entry is copied or recomputed. Swapping two address bits is the simplest case of the interchange on the page [Address-field interchange](address-interchange.md).

Because a permutation only relocates values, it adds no rounding. The paper's address-swap subroutine <cite data-source="paper">returns an exact permutation of the encodings before coefficient arithmetic resumes</cite>, so its internal bit operations change no coefficient.
