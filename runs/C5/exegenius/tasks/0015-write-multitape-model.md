## This page

Concept: Fixed multitape Turing machine model
Gloss: One fixed finite alphabet and a fixed finite number of one-dimensional tapes; each step reads/writes one cell per tape and moves each head at most one cell, so moving data costs time.

## Where the argument relies on this page

- One fixed-tape Turing machine multiplies n-bit integers in $O(n(\lg n)^{1-\kappa})$ time with $\kappa=2^{-182}$. (on [Integer multiplication in O(n (lg n)^(1−κ)) time](main-theorem.md))
- In the fixed multitape model data movement costs time, so arrays are laid out in address order and fields of addresses are contiguous chunks. (on [Array addresses, fields and tape layout](address-fields-layout.md))

## Pages that build on this one

- The n log n conjecture and history: Schönhage and Strassen proposed n log n as optimal multiplication cost; Schönhage–Strassen, Fürer and Harvey–van der Hoeven reduced upper bounds down to O(n log n).
- Array addresses, fields and tape layout: Arrays are stored on tape in row-major address order; address bit-fields (chunks) are contiguous and permuting them costs more than scanning.

  > A machine has one fixed finite alphabet and one fixed finite number of one-dimensional tapes. A step reads and writes at most one cell on each tape and moves each head by at most one cell. Fixed tracks and finitely many work tapes change time by a fixed factor. We distinguish moving one digit in a fixed radix, which needs a bounded number of scans, from interchanging fields whose numbers of digits grow. The latter permutation will be realized in Section~\ref{sec:tape-interchange} by computing XOR combinations of intermediate data streams. The present section supplies the elementary scans it uses.
