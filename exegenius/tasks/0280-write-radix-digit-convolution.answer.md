Radix-digit convolution is a reduction of [exact integer multiplication](exact-integer-multiplication.md) that writes each input as a polynomial in a power of two whose coefficients are its digits, so that the product becomes a convolution of short integer coefficients. It is the first step of the argument for [Integer multiplication below n log n](main-theorem.md): the [Chinese-remainder map](chinese-remainder-map.md) and [carry propagation](carry-propagation.md) pages build on the coefficients it produces.

The paper states the reduction in one sentence: <cite data-source="paper">Splitting the inputs into radix digits reduces multiplication to convolution of short integer coefficients.</cite>

**Digits.** Let $x$ and $y$ be the two binary strings, each of $n$ bits, with $n \ge 2$. The digit width $b$ is the number of bits in each digit. The paper takes <cite data-source="paper">b = ⌈log2 n⌉</cite>, so that $b \ge 1$ and $2^b \ge n$; the second holds because $2^{\lceil \log_2 n\rceil} \ge 2^{\log_2 n} = n$. Cut each input into blocks of $b$ bits, counting from the least significant end and padding the last block with leading zeros. Each block is a digit with value between $0$ and $2^b-1$, and $2^b$ is the radix. Let $N = \lceil n/b\rceil$ be the number of digits in each input. Let $x_i$ be the digit of $x$ at position $i$, for $0 \le i \le N-1$, so that $x = \sum_{i=0}^{N-1} x_i (2^b)^i$. The digits $y_j$ of $y$ are defined the same way, with position $j$.

**Polynomials.** Let $z$ be a formal variable (the letter $z$ changes meaning here). Let $P_x(z) = \sum_{i=0}^{N-1} x_i z^i$ be the polynomial of $x$, and $P_y(z) = \sum_{j=0}^{N-1} y_j z^j$ that of $y$. Substituting $z = 2^b$ returns the inputs: $P_x(2^b) = x$ and $P_y(2^b) = y$. Let $k$ be the position of a product coefficient, running from $0$ to $2N-2$. Let $c_k$ be the integer coefficient of $z^k$ in the product $P_x(z)P_y(z)$. Then
$$c_k = \sum_{i+j=k} x_i\, y_j,$$
with $i$ and $j$ running over $0 \le i, j \le N-1$. This is the convolution of the digit sequences $(x_i)$ and $(y_j)$, so $c_k$ is its $k$-th entry. Substituting $z = 2^b$ gives $xy = \sum_k c_k (2^b)^k$, so the product is recovered from the $c_k$. The $c_k$ are not yet binary digits, since a coefficient can exceed $2^b-1$.

**Coefficient size.** Each $c_k$ is a sum of at most $N$ products $x_i y_j$, and each product is at most $(2^b-1)^2$, so $0 \le c_k \le N(2^b-1)^2$. <cite data-source="paper">Every product coefficient obeys</cite> this bound. Since $N \le n \le 2^b$, we get $c_k \le 2^b \cdot (2^b)^2 = 2^{3b}$, with strict inequality because $(2^b-1)^2 < 2^{2b}$. Each coefficient therefore fits in $3b$ bits. Since $b = \lceil \log_2 n\rceil < \log_2 n + 1$, this is fewer than $3\log_2 n + 3$ bits, which is $O(\log n)$.

**Example.** Take $n = 4$. Then $b = 2$ and $N = 2$. Let $x = 1101$ (value 13) and $y = 1011$ (value 11). Splitting into base-4 digits from the least significant end gives $x_0 = 1$, $x_1 = 3$, $y_0 = 3$ and $y_1 = 2$. The coefficients are $c_0 = x_0 y_0 = 3$, $c_1 = x_0 y_1 + x_1 y_0 = 2 + 9 = 11$ and $c_2 = x_1 y_1 = 6$. Check: $3 + 11 \cdot 4 + 6 \cdot 16 = 143 = 13 \cdot 11$. The coefficient $c_1 = 11$ is larger than a digit, so the sequence is not yet the binary product. [Carry propagation](carry-propagation.md) converts it into one.

**Why the split lowers cost.** Without the split, the digits are single bits ($b = 1$). There are then $2n-1$ coefficients, each at most $n$, so each needs about $\log_2 n$ bits, and the stored volume is $\Theta(n\log n)$ bits. With $b = \lceil\log_2 n\rceil$ there are $2N-1$ coefficients of $3b$ bits, a volume of $(2N-1)\cdot 3b$ bits. Since $N \ge n/b$ and $N \le n/b+1$, this lies between $6n-3b$ and $6n+3b$ bits, which is $\Theta(n)$ because $b = O(\log n)$.

**Where the cost goes.** The convolution is computed with [Fourier transforms](discrete-fourier-transform.md), and each transform level applies [Butterfly](butterfly.md) operations to the whole array. On a tape, a level reads the array in order and writes each entry back at its new address, so the head must visit every stored bit once per level, and its time is proportional to the stored bits. The arithmetic is proportional too: each butterfly acts on one coefficient of $O(\log n)$ bits, so the number of operations is proportional to the number of stored bits, and each operation costs $O(\log n)$ bit steps. A level therefore costs $\Theta(n)$ after the split, and the $\Theta(\log n)$ levels multiply this. The paper's count is that <cite data-source="paper">Scanning an array of Θ(n) stored bits at each of Θ(log n) transform levels already costs Θ(n log n).</cite> The split alone thus leaves a total of $\Theta(n\log n)$, and <cite data-source="paper">We therefore need savings in both movement and arithmetic.</cite>
