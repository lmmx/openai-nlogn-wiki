An address field is a contiguous block of address bits of an array. An address interchange exchanges two disjoint fields of the same width, which is the operation the multiplication algorithm uses to change how an array's entries are laid out on the tape. The paper also calls a field an address chunk or a chunk. <cite data-source="paper">Fast address interchanges organize the layouts</cite>, and the later pages build on this operation.

An array is stored as a single ordered stream, and its address is implicit in each entry's position. The array's address set is a product of ranges, and the entries are <cite data-source="paper">stored in lexicographic order, with the first coordinate most significant</cite>. For an array of $2^k$ entries with binary addresses, the address of an entry is therefore a string of $k$ bits, read from most significant to least significant.

An address field is a run of consecutive bits in this address string. Write $u$ for the number of bits in each of the two fields being interchanged. Two fields are disjoint when they share no bit position. The interchange swaps the contents of the two runs and leaves every other address bit where it is. The paper's statement is for an array <cite data-source="paper">whose addresses form a complete Cartesian product</cite>, with two disjoint contiguous fields of $u$ bits.

Take $u = 2$ and an array of 16 entries with 4-bit addresses, and let the two fields be bit positions 1–2 and bit positions 3–4. The interchange sends the address $0110$ to $1001$, because the field $01$ and the field $10$ trade places. The entry stored at $0110$ therefore sits at $1001$ afterwards, and the entry at $0011$ moves to $1100$. Every other address in the array is moved by the same rule.

Only the fields are exchanged, not the entries' values, so an interchange is a permutation of addresses. Its usefulness depends on the fields being contiguous, because a contiguous run of address bits can be moved as one block.
