The padded transform box is the array of a [Multidimensional transform](multidimensional-transform.md) over its $D$ padded axes: the full array of entries that results once every axis has been padded to its chosen length. It is the one fixed array in which the coefficients are laid out and transformed, so every step that moves data is charged against the same size.

For each axis $s$, running from $1$ to $D$, let $W_s$ be the valid length, the number of data entries along that axis, and let $t_s \ge W_s$ be its padded length. Padding an axis means appending zero entries until it has length $t_s$. Let $N = t_1 t_2 \cdots t_D$ be the number of entries of the box, valid or zero. An address $\mathbf{x} = (x_1,\dots,x_D)$ with $0 \le x_s < t_s$ for every $s$ names one entry of the box. The valid region is the set of addresses with $x_s < W_s$ for every $s$; all other entries are zero.

The padded transform box is built from the [radix-digit coefficients](radix-digit-convolution.md) of the two integers, placed on pairwise coprime valid lengths $W_1,\dots,W_D$ by a [Chinese-remainder map](chinese-remainder-map.md) $\Phi$. <cite data-source="paper">Let s1 , . . . , sd be the pairwise coprime source lengths</cite>, so the coefficients form a cyclic convolution of length $S = W_1 W_2 \cdots W_D$. <cite data-source="paper">Its powers therefore run</cite> through all target basis monomials exactly once, so each coefficient occupies one valid address. <cite data-source="paper">Hence Φ is an isomorphism and preserves cyclic</cite> convolution, so the valid region computes the same product as the cyclic convolution, and the zero entries outside it add nothing.

Some steps move data between valid and invalid addresses. Expanding axis $s$ updates the box along each [line](axis-line.md) whose other coordinates are valid. It applies the one-dimensional forward map $A_s$ to each such line, from length-$W_s$ to length-$t_s$ vectors: <cite data-source="paper">read its first si values and apply Aei , then write the resulting ti values</cite>. It writes $t_s$ zeros on every other line. Compressing axis $s$ instead applies the backward map $B_{0,s}$, from length-$t_s$ to length-$W_s$ vectors, to each line whose other coordinates are valid, writes its $W_s$ outputs followed by $t_s - W_s$ zeros, and writes a zero line on every other line. Each such step writes every address of the box, valid or not. <cite data-source="paper">The box therefore keeps its full size</cite>: the padded lengths $t_s$ do not change, so $N$ is the same before and after.

Take $D = 2$, $t_1 = 8$, $W_1 = 5$, $t_2 = 4$ and $W_2 = 3$. The box has $N = 32$ entries. The valid region is the $15$ addresses with $x_1 < 5$ and $x_2 < 3$, and the other $17$ entries are zero. Compressing axis 1 writes $5$ outputs and then $3$ zeros on each line whose other coordinate is valid, so each such line still has $8$ entries.

The padded transform box is rearranged by the coordinate permutations of the [Transform identity with retained permutations](transform-identity.md), which move entries within this one fixed array instead of sorting the data into a new array. They need not be <cite data-source="paper">executed as separate full sorts</cite>. Moving an axis past its neighbor interchanges two address fields. <cite data-source="paper">These are exact permutations of the padded box</cite>, so they change neither norms nor errors.
