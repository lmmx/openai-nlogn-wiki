A tape procedure is a fixed procedure that rearranges the contents of a Turing machine's tapes, such as the address fields of an array, in a bounded number of scans of those tapes. The main result of the wiki uses tape procedures to move the data of its transforms between layouts, so that the movement costs less than scanning the data at every transform level.

The machine model is the [Fixed-tape machine model](fixed-tape-model.md): the machine has one fixed finite alphabet and a fixed finite number of one-dimensional tapes. Each step <cite data-source="paper">reads and writes at most one cell on each tape and moves each head by at most one cell</cite>. A scan is one pass of a head along a stretch of tape, so a procedure that makes a bounded number of scans of its data takes a bounded multiple of the time of one scan.

Consider an array with two address coordinates, each in $\{0,1\}$, so the array has four entries. Its addresses are <cite data-source="paper">stored in lexicographic order, with the first coordinate most significant</cite>, so the tape holds the entries at $(0,0)$, $(0,1)$, $(1,0)$, $(1,1)$ in that order. Exchanging the two coordinates moves the entry at $(0,1)$ to the address $(1,0)$, and the entry at $(1,0)$ to the address $(0,1)$. Afterwards the tape holds the entries at $(0,0)$, $(1,0)$, $(0,1)$, $(1,1)$: the two middle cells have traded places and the other two stay where they are. This is a permutation of the digit values at two positions, the kind of operation that the paper's elementary lemma says <cite data-source="paper">takes O(V ) steps on a fixed number of one-dimensional tapes</cite>, where $V$ is the number of stored bits.

Tape procedures are needed because a full scan at every transform level is too costly: <cite data-source="paper">Scanning an array of Θ(n) stored bits at each of Θ(log n) transform levels already costs Θ(n log n).</cite> The savings must come in movement and in arithmetic, and <cite data-source="paper">Two tape procedures supply them</cite>. The first tape procedure is illustrated by [Address-field interchange](address-interchange.md), which interchanges two disjoint contiguous address fields of $u$ bits in an array. The paper gives its cost as <cite data-source="paper">O(V uτ ) for a fixed τ < 1</cite>. Because the exponent is below one, the cost grows more slowly than linearly in the field width $u$. The second procedure applies the [butterfly](butterfly.md) <cite data-source="paper">simultaneously on selected coordinate bits of the numerical arrays</cite>, so one pass handles every selected bit together.
