An address field is a run of bits in the [address](address.md) of an array, consecutive in position, and it is the unit that an address interchange exchanges with another field of the same width. The multiplication algorithm, which multiplies two exact integers on tapes, uses these interchanges to change how an array's entries are laid out on the tape: <cite data-source="paper">Fast address interchanges organize the layouts</cite>. The paper also calls a field an address chunk or a chunk, as in <cite data-source="paper">interchange two equal address chunks on tape</cite>.

An array is stored as a single ordered stream, <cite data-source="paper">stored in lexicographic order, with the first coordinate most significant</cite>, and its address is implicit in each entry's position: <cite data-source="paper">An address is implicit in an entry’s position in this ordered stream</cite>. The set of addresses of an array is a product of ranges: each coordinate of the address takes every value in its range, so all combinations occur. For example, the 16 addresses $\{0,1\}\times\{0,1\}\times\{0,1\}\times\{0,1\}$ are all 4-bit strings.

Write $u$ for the number of bits in each of the two fields being interchanged. Bit positions are counted from the most significant bit, starting at 1, so position 1 is the leftmost bit. A field of $u$ bits is a run of $u$ consecutive positions. Two fields are disjoint when they share no position. The interchange swaps the contents of the two fields and leaves every other bit where it is. The paper states its result for <cite data-source="paper">interchanges two disjoint contiguous address fields of u bits in an array</cite>, with <cite data-source="paper">whose addresses form a complete Cartesian product</cite>.

Take $u = 2$ and an array of 16 entries with 4-bit addresses, and let the two fields be bit positions 1–2 and bit positions 3–4. The interchange sends the address $0110$ to $1001$, because the field $01$ and the field $10$ trade places. The entry stored at $0110$ therefore sits at $1001$ afterwards. Likewise the field $00$ and the field $11$ of the address $0011$ trade places, so the entry at $0011$ moves to $1100$.

Each address field is moved by a [permutation](permutation.md) of addresses, because the interchange exchanges only the fields and not the entries' values.

Contiguity is what lets the move work on the tape in blocks. Entries that agree on every bit outside the field at positions 3–4 form one run of consecutive stream positions: the four entries that begin with $01$ occupy stream positions 4 to 7, counting from 0. A contiguous field therefore leaves whole blocks of consecutive entries together, so a procedure can handle each block in one pass instead of picking out single entries scattered across the stream. The paper states its procedure for contiguous fields only.
