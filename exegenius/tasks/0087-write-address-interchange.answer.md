Address-field interchange is a tape procedure that swaps two disjoint contiguous address fields of an array in time that grows like a power of the field width. Multiplication rearranges its arrays by such swaps, and the bound below shows each swap costs less than linear time.

An address is a string of bits, and an address field is a block of consecutive bits inside it. Two fields are disjoint when they share no bit. The addresses form a complete Cartesian product, so every combination of field values occurs as exactly one address. The procedure runs on the [Fixed-tape machine model](fixed-tape-model.md), in which each step reads and writes at most one cell on each tape.

Let $u$ be the number of bits in each field, and let $V$ be the number of stored bits in the array. Let $\tau<1$ be a fixed number, the exponent in the bound $O(V u^{\tau})$. <cite data-source="paper">Its cost is O(V uτ ) for a fixed τ < 1.</cite> For fixed $V$ this grows like a power of $u$ with exponent below one, so more slowly than linearly.

The method is not a direct copy. <cite data-source="paper">Our address procedure forms XOR combinations of intermediate data</cite>, even though its final effect is a permutation. Let $a$ and $b$ be the two fields, read as blocks of bits at matching positions, and let $\oplus$ denote bitwise exclusive or (XOR). Three XOR steps swap them:
$$(a,b)\to(a,\;a\oplus b)\to(b,\;a\oplus b)\to(b,\;a).$$
The first step replaces $b$ by $a\oplus b$. The second replaces $a$ by $a\oplus(a\oplus b)=b$. The third replaces $b$ by $(a\oplus b)\oplus b=a$. For example, $a=10$, $b=01$ give $(10,01)\to(10,11)\to(01,11)\to(01,10)$. The source states the same schedule with signs, using $x,y$ for $a,b$ (these letters change meaning here): <cite data-source="paper">(x, y), the three stages give (x, y + x), then (−y, y + x), then (−y, x).</cite> Over bits $-y=y$, so the signs vanish and leave the chain above.

Each XOR step is a pointwise combination applied at all matching addresses at once. The interchange is carried out by a [Linear networks and frames](linear-network-frames.md) network. The network restores its [scratch storage](scratch-storage.md) to its starting contents, whatever they were. The source says the network is fixed and <cite data-source="paper">restores every auxiliary value.</cite> So the result does not depend on the scratch starting contents: <cite data-source="paper">The final permutation is exact for arbitrary initial auxiliary values.</cite>

The cost bound comes from a recursion on the field width. Let $m$ be a fixed base, so a width $u=m^k$ has $k=\log_m u$ levels, and let $W$ be the number of equal pieces the volume is cut into at each level. A call of width $u$ makes $s$ calls of width $u/m$, each on one piece, where $s$ is the number of such calls. Let $j$ count the levels below the top call. Level $j$ therefore does work $V(s/W)^j$. The source's counting gives $s/W<m^{\tau}$, so after $k$ levels the work is below $V(m^{\tau})^k=Vu^{\tau}$. <cite data-source="paper">the resulting recurrence saves a power of the chunk width.</cite>

This saving is what multiplication needs, since <cite data-source="paper">Fast address interchanges organize the layouts</cite> of its transforms. The main result, [Integer multiplication below n log n](main-theorem.md), relies on it.
