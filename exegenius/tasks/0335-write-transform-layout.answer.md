A transform layout is a permutation of record addresses that gathers the selected bits of all participating axes at one common offset. The transform layout prepares the input for each [simultaneous butterfly layer](simultaneous-butterfly-layer.md) of a transform round. Its cost is charged in the bound for [Integer multiplication below n log n](main-theorem.md).

Each entry of a multidimensional array sits at a binary address; its bits are the *address bits*. Each coordinate of the array is an *axis*, and each address holds one *record*, a polynomial with $r$ complex coefficients. A *chunk* is a run of consecutive address bits. A *selected bit* is an address bit on which a round's butterfly acts: the [butterfly](butterfly.md) $H_0(\xi,\eta)=((\xi+\eta)/2,(\xi-\eta)/2)$ pairs two entries that differ in that bit. A *transform round* applies one such butterfly on each participating axis.<cite data-source="paper">A round applies one current H0 on each participating axis.</cite>

A round needs its selected bits in $D$ consecutive $K$-bit chunks, each selecting the bit at one common offset $\rho$, counted from the least significant end, with $0 \le \rho < K$.<cite data-source="paper">Its D consecutive K-bit chunks each select the bit at</cite><cite data-source="paper">one common offset 0 ≤ ρ < K, counted from the least significant end.</cite> One pass applies $H_0$ to the selected bit of every chunk, which needs those bits at one offset. Without this shape, a round would need one pass per axis.<cite data-source="paper">separate butterfly factors would require D whole-array passes.</cite>

The transform layout is an explicit [permutation](permutation.md) $\mathcal{L}$ of record addresses.<cite data-source="paper">a record at address x moves to address Lx, while its polynomial suffix stays intact.</cite> A record's coefficients form a contiguous block of trailing address bits, its [polynomial suffix](polynomial-ring.md). The transform layout keeps each element of the [polynomial ring](polynomial-ring.md) that a record holds intact.

Address bits are read in *physical order*, leading end first. A long axis has $\lg r$ address bits and a short axis has $\lg r-1$, where $\lg r$ is the base-two logarithm of $r$.<cite data-source="paper">Call an axis long if ai = ℓ and short if ai = ℓ − 1.</cite> The first phase builds a *prefix*, the leading part of the physical order: the top bit of each long axis, then the bits at positions below $(\lg r-1)\bmod K$, counted from the least significant end, from the highest down, axes in order within each position. Here $(\lg r-1)\bmod K$ is the remainder of $\lg r-1$ on division by $K$: the bits left over after full $K$-bit chunks.<cite data-source="paper">Move each listed slot immediately after the prefix already formed, leaving all other slots</cite>

Each axis's bits outside the prefix, positions $(\lg r-1)\bmod K$ up to $\lg r-2$, form $\lfloor(\lg r-1)/K\rfloor$ consecutive $K$-bit chunks, on long and short axes alike. Number them from the highest down; this number is the *chunk index*. Chunk exchanges then put the $D$ chunks with one index next to each other.<cite data-source="paper">exchange the chunk currently there with the required chunk if they differ.</cite>

A round at a position $\delta$, counted from the least significant end, selects that bit on each axis, at offset $\rho = (\delta-((\lg r-1)\bmod K))\bmod K$ within its chunk. The offset is the same on every axis, because each axis's chunks tile its outside bits upward from position $(\lg r-1)\bmod K$ in blocks of $K$. So each group of $D$ chunks with one index shares one offset.<cite data-source="paper">in each of the D consecutive chunks with the same chunk index j.</cite>
