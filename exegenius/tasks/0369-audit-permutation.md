## Page to audit (`permutation`)

````markdown
# Permutation

A permutation is the rearrangement that the paper's procedures use to move stored data from one position to another. The page [Address-field interchange](address-interchange.md) builds on it, because swapping two blocks of address bits is a permutation of an array's addresses.

Here $S$ is a finite set of positions, and $\pi$ is the permutation, the map that sends each position to its new position. A permutation of $S$ is defined as a [bijection](bijection.md) of $S$ onto itself: a map $\pi$ from $S$ to $S$ that is one-to-one and onto, so every element of $S$ is the image of exactly one element of $S$. Because $\pi$ is a bijection, it has an inverse $\pi^{-1}$ that sends every image back to its source, so a rearrangement by $\pi$ can always be undone.

**Rearranging a sequence.** Take $S=\{1,2,3,4\}$ and let $\pi$ send $1$ to $3$, $2$ to $1$, $3$ to $4$ and $4$ to $2$. Apply $\pi$ to the sequence $(\alpha,\beta,\gamma,\delta)$, whose entries sit at positions $1,2,3,4$, by moving the entry at position $i$ to position $\pi(i)$. The entry $\alpha$ goes to position 3, $\beta$ goes to position 1, $\gamma$ goes to position 4 and $\delta$ goes to position 2. The result is $(\beta,\delta,\alpha,\gamma)$. Every position of the result is filled exactly once, so no entry is lost or copied.

The bijection property is what makes this work. If $\pi$ were not one-to-one, two entries would land in the same position and one would be overwritten. If $\pi$ were not onto, some position would receive nothing. Both failures would destroy data, while a bijection only moves it, and $\pi^{-1}$ moves it back.

**Permutations of arrays.** The paper applies permutations to arrays, whose entries are stored at addresses. Write $u$ for an address, the position of one entry in an array. An address permutation $\pi$ moves the entry at address $u$ to address $\pi(u)$. If $A$ is an array, the moved array $\pi A$ satisfies $(\pi A)(\pi(u))=A(u)$ for every address $u$: the entry that was at $u$ is now read at $\pi(u)$. The moved array holds the same entries in new positions, so no entry is recomputed.

Moving a single digit in a fixed radix takes a bounded number of scans, but moving whole fields with growing numbers of digits needs more work.
````
