This page states the main theorem: a deterministic multitape Turing machine multiplies two integers exactly in worst-case time that beats the conjectured $n\log n$ bound. Here $n$ is the number of bits in each input integer. $O(g)$ means at most a constant times $g$ for all large inputs. $\lg n = \max\{\lceil \log_2 n\rceil, 1\}$ is the base-2 logarithm rounded up and at least 1. The constant $\kappa = 2^{-182}$ is the power-saving exponent, the fixed amount by which the power of $\lg n$ falls below one. The time bound $O(n(\lg n)^{1-\kappa})$ disproves the [Schönhage–Strassen n log n conjecture](nlogn-conjecture.md).

The first step reduces the integer product to a carried convolution of radix-$2^b$ digit sequences, as in [Multiplication as convolution of digits](convolution-reduction.md). The second computes that convolution by transforms. Each transform level scans $\Theta(n)$ bits, so only savings in both movement and arithmetic beat $n\log n$ <cite data-source="paper">We therefore need savings in both movement and arithmetic.</cite>.

Two tape procedures supply them. The algorithm performs its address permutations by [fast address interchange](address-interchange.md), whose cost is $O(V u^\tau)$ for $\tau<1$. The algorithm builds each transform level from [simultaneous butterfly layers](simultaneous-butterfly-layer.md), each acting on one address bit, whose cost is $O(V d^{\lambda'})$ for $\lambda'<1$. The power saving follows from [Recursive power saving](recursive-power-saving.md). A network with $s$ smaller calls on $W$ roles and parameter $m$ makes each level of recursion multiply the cost by $s/W$ while dividing the parameter by $m$. Since $s/W<m$, the cost is a power of the parameter with exponent $\log_m(s/W)<1$.

The algorithm arranges its digits by the [Chinese-remainder address map](chinese-remainder-address-map.md) on distinct prime cyclic axes. It computes its transforms by [Gaussian resampling](gaussian-resampling.md), which expresses each prime-length transform through power-of-two axes. It converts its middle transform by [Bluestein's chirp identity](bluestein-chirp.md) into a normalized cyclic convolution. It places its last cyclic coordinate in the [polynomial ring modulo $y^r+1$](polynomial-ring-y.md), where its wrap is a signed shift. It computes its forward transforms by [synthetic polynomial transforms](synthetic-transform.md), which keep frequency order through their pointwise product. It computes its polynomial products with the [Harvey–van der Hoeven O(n log n) multiplication](harvey-hoeven-multiplier.md), used as a subroutine on packed integers from [signed Kronecker packing](kronecker-packing.md).

Each stored coefficient keeps $p$ bits after the binary point, where $p$ is the working precision, so truncation rounds it to a multiple of $2^{-p}$. A contraction is a linear map that does not increase the largest coefficient magnitude, and each transform layer is one. A contraction does not enlarge an error already present, so error grows only at truncations, each adding less than $\sqrt2\,2^{-p}$. Choosing $p$ large enough as a function of $n$ keeps the total below $1/2$, since there are only as many truncations as transform rounds. The algorithm recovers its exact product by [exact recovery by rounding](rounding-recovery.md), which rounds each coefficient to the nearest integer and propagates carries.
