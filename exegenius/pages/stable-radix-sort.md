Stable radix sort orders records by a multi-bit key in one pass per key bit, starting from the least significant bit. In the argument it puts the extracted exceptional records into the order of their destination keys, so that one further scan can return each record to its final position.

A *record* is an item carrying a *key*, and a *sort* rearranges records into increasing key order. A sort is *stable* when records with equal keys come out in the same relative order they had on input.

The letters in the next paragraph take the meanings given there, which differ from their meanings on earlier pages. Let $M$ be the number of records in the full stream, and let $w$ be the number of bits in each key. Write a key as $q = q_{w-1}\cdots q_0$, where $q_t \in \{0,1\}$ is its bit of weight $2^t$ at each bit position $t$ from $0$ to $w-1$. So $q_0$ is the least significant bit, and $q_{t-1}$ is the bit just below position $t$.

The method makes $w$ passes, one for each bit position $t = 0, 1, \dots, w-1$ taken in turn. Pass $t$ orders the current list by the single bit $q_t$: all records with $q_t = 0$ come first, then all records with $q_t = 1$, and within each of the two groups the current relative order is kept. Each such pass is a *stable bit sort*. After the last pass the list is sorted by the whole key.

The order of the passes matters. After pass $t$, the list is sorted by the low $t+1$ bits $q_t \cdots q_0$, with ties kept in input order. The method is proved correct by [mathematical induction](mathematical-induction.md) on $t$, the pass index. The base case is pass $0$ alone, which sorts by $q_0$. For the step, suppose the list is sorted by $q_{t-1} \cdots q_0$ before pass $t$. Two records with different $q_t$ are ordered correctly by pass $t$ alone, whatever their lower bits. Two records with equal $q_t$ keep their relative order, which by hypothesis already respects the lower bits. Stability is what lets earlier passes survive later ones: a pass that could reorder records with equal bits would undo the order on the lower bits.

Take $w = 2$ and $M = 4$, with records A, B, C, D in that input order and keys $q_1 q_0$ equal to 10, 01, 10, 00. Pass 0 sorts by $q_0$: the records with $q_0 = 0$ are A, C, D, and the record with $q_0 = 1$ is B, so the list becomes A, C, D, B. Pass 1 sorts by $q_1$: in the list A, C, D, B the bits $q_1$ are 1, 1, 0, 0, so the zeros are D, B and the ones are A, C. The list becomes D, B, A, C, with keys 00, 01, 10, 10. Records A and C have equal keys and keep their input order, which is what pass 1 must preserve.

In the argument, stable radix sort sorts the records of the [exceptional set](exceptional-set.md), taken out of the full stream for separate sorting. Each extracted record has a *hole*, a marked position in the full stream where the record belongs, and a *destination key*, the rank of that hole. The rank of a position is its index counted from $0$ at the first record of the stream, so the ranks run from $0$ to $M-1$.

The *destination map* sends each exceptional address to the address its record must reach, and it permutes the exceptional set. <cite data-source="paper">Since T0 S0−1 permutes B</cite>. Hence <cite data-source="paper">these keys are distinct and are exactly the ranks of the marked</cite> holes. The full stream stays untouched while the sort runs, and <cite data-source="paper">stable binary radix sorting scans only the extracted records and keys, least significant key</cite> bit first.

Sorting the keys therefore lists the holes in rank order. Each key is the rank of exactly one hole, and every hole has exactly one key, so the $i$-th smallest key is the rank of the $i$-th hole in rank order. The record carrying that key belongs in that hole.

The records are then put back with one further scan of the full stream. <cite data-source="paper">One forward full-stream scan reinserts the sorted records.</cite> The scan runs forward, so it meets the holes in increasing rank order, and at each hole it inserts the next record of the sorted list. That record is the one whose key is the rank of that hole.

The key width follows from the number of records. For $M \ge 2$, every rank from $0$ to $M-1$ fits in $\lceil \log_2 M \rceil$ binary digits, so the key width is $w = \lceil \log_2 M \rceil$. Here $A_{\mathrm{rect}}$ is the paper's size parameter for its integers. The paper defines it as <cite data-source="paper">Arect = ⌈log2 (2V )⌉</cite>. The paper's destination keys are <cite data-source="paper">padded to ⌈log2 M ⌉ ≤ Arect bits</cite>, which gives $w \le A_{\mathrm{rect}}$.

The method takes its pass count from the [base-2 logarithm](base-two-logarithm.md) of $M$, rounded up. So it makes $w = \lceil \log_2 M \rceil$ passes, and since $w \le A_{\mathrm{rect}}$, at most $A_{\mathrm{rect}}$ of them. Stable radix sort makes each pass one [scan](stream.md) of the extracted records and keys.
